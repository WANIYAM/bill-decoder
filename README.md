# Utility Bill Decoder (WTQ Build Track)

This project reads electricity bill images from K-Electric (KE), LESCO and IESCO,
extracts structured Level 1 bill data into JSON, computes supporting statistics,
and generates customer-facing Level 2 answers for 12 bill questions.

The solution is designed to run locally from a project folder and generate the
required CSV outputs in `output/`.

## Requirements

- Python 3.12.10
- A Google AI Studio API key for Gemini 3.5 Flash-Lite
- Access to the repository folder containing the source files and bill images

## Setup

Create a virtual environment, install dependencies, and copy the example
environment file:

Windows PowerShell:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
Copy-Item .env.example .env
```

macOS/Linux:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
```

Edit `.env` and replace the placeholder with your real Google AI Studio API key:

```env
MODEL_PROVIDER=google
MODEL_NAME=gemini-3.5-flash-lite
API_KEY=your-api-key-here
```

## Run the project

From the project root, generate both CSVs from the bill image folder and the
CSV templates:

```bash
python run.py --bills train/bills --csv fake_csv --out output --no-cache
```

What this does:

- reads `level1.csv` and `level2.csv` from the `--csv` folder
- processes each matching bill image in `--bills`
- writes the filled results to `output/`
- validates that both output CSVs have the expected row counts and valid output
  content

If you want to regenerate the sample templates from bill IDs in the training set:

```bash
python make_fake_templates.py
```

## Validate output and package for submission

Project health check:

```bash
python audit.py
```

Create a clean submission ZIP without including local secrets, caches, test data,
training assets, or the virtual environment:

```bash
python package.py
```

This creates `bill-decoder.zip` in the project root.

## How it works

1. `extract.py` loads the bill image and sends it to the configured model.
2. `level1.py` extracts structured bill data and uses `postprocess.py` to
   normalize numbers, CR credits, dates, and charge/tax types.
3. `history.py` extracts usage history, billing history, and extra bill markers.
4. `stats.py` computes usage statistics, averages, seasonal comparisons, payment
   checks, and bill estimates in Python.
5. `level2.py` answers the 12 customer questions using the bill image, extracted
   facts and computed statistics.
6. `run.py` writes both CSVs, retries failed calls, caches successful results,
   and validates the output.

## Error handling

The pipeline is designed to continue running even when a model call fails or a
bill is partially unreadable:

- model requests retry with backoff-style handling
- extracted Level 1 values are normalized defensively
- fallback answers are used for Level 2 where a bill does not provide enough
  readable information
- output validation prevents empty answer cells from being written silently

This ensures the pipeline never fails the whole run just because one bill is
hard to read.

## Notes

- `.env` is intentionally ignored by Git and must not be submitted.
- The local `cache/` directory is used for per-bill reuse of successful outputs.
- `train/` contains training bills and expected outputs, not submission artifacts.
- `output/` contains the generated Level 1 and Level 2 results used for the
  final submission pipeline.

## Error handling

Model requests are retried with backoff. If extraction fails, the program
produces null-filled Level 1 data and fallback Level 2 answers, so the run can
continue without leaving answer cells empty.
